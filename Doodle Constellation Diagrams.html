This page is the diagram atlas for the Doodle Constellation Architecture article. Component names and arrow labels are copied from it. It shows a design that has not been built. Every size, count and time here is a target or an example, not a measurement. The reference build is a desktop program in OCaml with raylib; each core component sheet now shows the algorithm as set in that build, with the GIMP code it is adapted from, and section 11 maps the modules.

Rounded box: store. Square corners: outside service. Pill: person or device. Dashed red: gap.

A person draws a shape on a phone and the system finds real stars that make the same shape, shows when they are best placed tonight, and reads out an invented story. In goes a freehand drawing, a location and a star list. Out come a sky view, a viewing time, a fit error, story audio and a share card.

The page draws that system from the outside in: who talks to it, what the layers are, what each component takes in and gives out, six runs of the program, how the three main records change, and what the finished product looks like. Colours show the tier. Shapes show the kind of thing. Dashed red boxes mark steps that no component owns yet.

Two matching methods carry the design: geometric hashing for the lookup and Procrustes analysis for the fit.

5.1 Sketch capture

The drawing surface. It records the finger or mouse path as ordered screen points and passes the stroke on.

OCaml + raylib build

ModuleCapture
raylib callsis_mouse_button_down MouseButton.Left, get_mouse_position () (or get_touch_position 0 on a touch screen)
Adapted fromgimpmotionbuffer.c drops moves smaller than half a screen pixel; gimppaintcore.c smooths each point as a Gaussian-weighted average of recent points. Commits e09520fb08, 082aa272a4.
What changesraylib gives one sample per frame and no per-event timestamps, so the filter step is 2 px and the Gaussian weight falls off with distance back along the stroke instead of with accumulated velocity.
type pt = { x : float; y : float }        (* in Geom *)
type t                                     (* raw and smoothed points *)
val empty  : t
val add    : t -> pt -> t                  (* filter + smooth one sample *)
val stroke : t -> pt array                 (* smoothed points, in order *)
Sample inputA path of 214 screen points drawn in 1.8 seconds, shape name “Bolt” (example).
Sample outputThe same 214 points in drawing order, with the name “Bolt”.

5.2 Stroke simplifier

Reduces hundreds of jittery points to the 5 to 9 corners that carry the shape, and refuses shapes that are too simple or too complex.

OCaml + raylib build

ModuleSimplify
raylib callsnone (pure OCaml)
Adapted fromgimpboundary.c simplify_subdivide: recursive subdivision with a cross-product distance test and a special case for closed loops.
What changesGIMP splits each piece at its midpoint. Doodle splits at the farthest point, which is true Ramer–Douglas–Peucker. The tolerance is relative to the drawing's size, and a retry loop lands the result on 5 to 9 corners. Smoothing moves into Capture, so the stroke arrives already smoothed.
type reason = [ `Too_simple | `Too_complex ]
val corners : Geom.pt array -> (Geom.pt array, reason) result
Sample input214 points forming a lightning bolt.
Sample output6 corners, for example (12,80) (60,20) (48,52) (96,40) (40,110) (70,70).

Lifecycle: none. This component holds no state between runs.

5.5 Candidate generator

Turns drawn corners into guesses about which stars they might be, by looking up shape keys in the index.

OCaml + raylib build

ModuleCandidates (uses Geom.sim_of_pair)
raylib callsnone (pure OCaml)
Adapted fromThe two-handle case of the Handle Transform tool, gimptoolhandlegrid.c case 2, and gimptoolpolygon.c fit_segment: one pair of points fixes scale, rotation and shift. Commit 2989bad35a.
What changesGIMP moves image handles. Doodle returns the transform as a record, and chooses the triangle's longest side as the pair because a long baseline gives the steadiest angle.
type sim = { s : float; theta : float; tx : float; ty : float }   (* in Geom *)
val sim_of_pair : Geom.pt -> Geom.pt -> Geom.pt -> Geom.pt -> Geom.sim
(* sim_of_pair a b a' b' maps a to a' and b to b' *)

type hypothesis = { corners : int array; stars : int array; sim : Geom.sim }
val generate : Index.t -> Geom.pt array -> hypothesis list
Sample input6 corners and the triangle index.
Sample outputAbout 3,120 guesses (example), such as corners 1-2-3 might be Rigel, Bellatrix, Saiph.

Lifecycle: none. This component holds no state between runs.

5.6 Similarity fitter and scorer

Tests each guess against the whole drawing, refines it, scores it, and keeps the best.

OCaml + raylib build

ModuleFitter (uses Geom.procrustes)
raylib callsnone (pure OCaml)
Adapted fromSnap-to-nearest with a running minimum inside a radius, from gimpimage-snap.c snap_point. The epsilon pivot guard in gimp-transform-utils.c mod_gauss and commit e7b6103cc8. The sign-flip fix in 17ec3d130e is the model for the mirror pass.
What changesGIMP only solves exact transforms from 4 point pairs. Least-squares Procrustes over all corners is new code. So are the rule that each star is used once and the score penalties.
val procrustes : Geom.pt array -> Geom.pt array -> Geom.sim option   (* in Geom *)
val rms        : Geom.sim -> Geom.pt array -> Geom.pt array -> float

type fit = { stars : int array; sim : Geom.sim; rms_deg : float; weak : bool }
val accept_limit : float                         (* degrees; owns gap G3 *)
val best : Catalogue.star array -> Candidates.hypothesis list -> fit option
Sample input3,120 guesses and the bright-star table.
Sample output6 stars, scale 8.4°, turn 112°, fit error 1.7° (example).

Lifecycle: none. This component holds no state between runs.

5.7 Sky renderer and morph animator

Draws the sky around the match, animates the drawing onto the stars, plays the story and builds the share card.

OCaml + raylib build

ModuleSky and Morph
raylib callsdraw_circle_v (stars), draw_line_ex (pattern lines), draw_spline_catmull_rom (moving stroke), draw_text (labels), get_frame_time () (clock), take_screenshot "card.png" (share card)
Adapted fromfit_segment moves a whole point list with one transform. gimpcoords-interpolate.c catmull draws the smooth curve. Commit 1cae93ac42 draws a polygon through a transform with clipping.
What changesGIMP applies the transform once. Doodle blends from the identity to the final transform over 1.5 s and reapplies it every frame. raylib's own draw_spline_catmull_rom replaces GIMP's interpolator.
val stereographic : centre:float * float -> float * float -> Geom.pt
val draw : view -> Fitter.fit option -> unit

type morph
val start   : drawn:Geom.pt array -> target:Geom.pt array -> morph
val step    : morph -> float -> morph        (* dt from get_frame_time () *)
val current : morph -> Geom.pt array -> Geom.pt array
Sample inputThe 6-star match, “2:40 a.m., south, 45° up” and a 30-second audio clip.
Sample outputA labelled sky with the bolt sliding onto the stars, and a card image on request.

6. Traces

These traces were drawn for the phone-and-server design. In the OCaml build, every step that crosses between browser and server is an ordinary function call inside one process, and the share card is a PNG saved by take_screenshot. Section 11 shows the frame loop that replaces them.

The write path is the share card, because it is the only thing the system hands back to be kept. The index is built in the background, in traces 1 and 4.

6.1 Trace 1: Startup

From launch until the first drawing can be made.

  1. Start service: the server begins loading.
  2. Catalogue rows: about 1,500 stars arrive from the file (target).
  3. Star positions: the store hands every star to the index builder.
  4. Triangle index: roughly a million shape keys, filed by bin, go to the candidate generator (example size).
  5. Open page: the user loads the app in a browser.
  6. Blank sky shown: the renderer draws an empty sky.
  7. Canvas ready: sketch capture is idle and waiting.

6.2 Trace 2: Draw and match (main path)

The user draws a bolt and sees it land on real stars.

  1. Finger path: about 214 points in order.
  2. Stroke: the same points, handed on.
  3. 6 corners: the bolt reduced to its turning points.
  4. Corners: the browser sends them to the server; no component owns this step yet (gap G1).
  5. Hypotheses: about 3,120 star-triple guesses (example).
  6. Positions, magnitudes: the bright-star table the fitter checks against.
  7. Matched region: the centre of the 6 stars, sent to the visibility calculator.
  8. Location and date: needed here, but nothing fetches it yet (gap G2).
  9. Star names: the six names plus the shape name go to narration.
  10. Best match: star IDs, scale, turn and a 1.7° fit error go to the renderer.
  11. Best time: 2:40 a.m., south, 45° up (example).
  12. Story audio: a 30-second clip arrives last, so the sky shows first.
  13. Sky view and morph: the bolt slides onto the stars; time and fit appear; the story plays.

6.3 Trace 3: Share card (write path)

The only thing the system writes for the user is a card image.

  1. Tap Share: the user asks for a card.
  2. Assemble card: the renderer combines the sky view, best time, fit error and a “story is fiction” tag. It already holds all of them.
  3. Card image: one image goes to the phone.
  4. Saved: the phone confirms.
  5. Share card: the user sees the finished card and can send it.

6.4 Trace 4: Index rebuild (background work)

An example refresh, for instance when the brightness cut changes. The schedule is a design choice, not a measured need.

  1. Refresh request: a timer or an operator asks for a reload.
  2. Catalogue rows: the file is read again.
  3. Star positions: the new table goes to the builder.
  4. Triangle index: the new index replaces the old one for later drawings. Drawings in progress keep the old index until they finish.

6.5 Trace 5: Failure, weak match

A drawing with long, evenly spaced corners. The fitter finds only a poor fit.

  1. Finger path, Stroke, Corners, Hypotheses: the normal path.
  2. Fit error 6.2°: the best guess is poor. Nobody owns the limit that makes it “weak” (gap G3).
  3. Weak-match flag: the renderer must be told.
  4. Best match: the attempt still arrives.
  5. Dimmed attempt, hint: the user sees the stars faded, the error, and a suggestion to draw fewer or tighter corners.

6.6 Trace 6: Failure, shape too simple

Three nearly straight corners match countless star groups, so the simplifier refuses them.

  1. Finger path, Stroke: a near-straight line is drawn.
  2. Too simple: the simplifier refuses it before any lookup.
  3. Try-again prompt: no arrow leads back to the user yet (gap G4).
  4. Cleared canvas, hint: the canvas is ready again with a message.

9. What done looks like

End-result pictures

Acceptance diagram

Acceptance checklist

  1. Opening the app shows a blank sky and an empty canvas, with no error message (T1).
  2. The first drawing can be made within about 10 seconds of the app starting (target) (T1).
  3. Drawing the seven stars of the Big Dipper returns the Big Dipper with a very small fit error (T2).
  4. Drawing a bolt returns six labelled stars and a fit error within about 3 seconds (target) (T2).
  5. The same bolt drawn small, large or turned lands on the same stars (T2).
  6. The sky view appears before the story audio, and the audio starts without a second tap on Play beyond the first (T2).
  7. A best time, a direction and a height are shown, and the time falls in the dark (T2).
  8. Tapping Share produces one card with sky, time, fit and a note that the story is invented (T3).
  9. The card appears on the phone and the sky view stays on screen (T3).
  10. After a refresh, the next drawing still returns a match and the old index is not used again (T4).
  11. A drawing with long, even corners shows a dimmed attempt, the fit error and a hint to draw fewer corners (T5).
  12. A near-straight line is refused with a hint, and the canvas is ready again (T6).
  13. Every matched star can be seen without a telescope (all traces that match).

10. Open gaps

Four steps in the traces have no owner in the architecture article. They are drawn as dashed red boxes above.

IdGapFound inQuestion
G1Browser-to-server hand-offTrace 2, step 4Who sends the corners to the server, waits for the reply, retries on failure and puts replies in order if the user draws again quickly?
G2Location and date sourceTrace 2, step 8Who asks the phone or user for location and date, and what does the visibility calculator get if the user says no?
G3Weak-match acceptance ruleTrace 5, step 2Who owns the error limit that separates a good match from a weak one, and who tells the renderer which side a result is on?
G4Refusal routeTrace 6, step 3When the simplifier refuses a shape, which component carries the reason back to the user?

How the OCaml build settles each gap:

IdStatus in the OCaml build
G1Closed. main.ml calls Simplify.corners, Candidates.generate and Fitter.best directly when the button is released. No network, so no retries or ordering problem.
G2Closed. Latitude and longitude come from command-line arguments with Buffalo as the default; the date comes from Unix.gettimeofday ().
G3Closed. Fitter.accept_limit owns the threshold and sets weak on the result; Sky dims weak results.
G4Closed. Simplify.corners returns Error `Too_simple or `Too_complex, and main.ml turns it into the on-screen hint.

11. OCaml and raylib build

The reference build is one dune project. A pure OCaml library in src/ holds every algorithm and never calls raylib, so it can be tested with dune test. A small executable in bin/ owns the window, reads the pointer and draws. Points cross from raylib to the library as a plain record, {x; y}, and go back to raylib as Vector2.t only at draw time.

Building from the diagrams

Minimal version (about two hours). Components: sketch capture, stroke simplifier, star catalogue store, invariant index builder, candidate generator, similarity fitter and scorer, with a flat plot in place of the renderer. Traces: 1, a cut-down 2, and 6. It must pass checks 1, 3, 4, 5 and 12. In OCaml: pre-built are the star CSV filtered to bright stars, Capture, Catalogue, Index, Candidates and the flat Sky plot. The small core left to write is the three algorithms adapted from GIMP, Simplify.corners, Geom.sim_of_pair and Geom.procrustes, plus Fitter.best, following the flow diagrams in sections 5.2, 5.5 and 5.6.

Hackathon version (a day). Adds the real sky renderer and morph, the visibility calculator, the narration layer, and trace 3. Unlocks traces 2, 3 and 5 in full and checks 2, 6 to 9, 11 and 13. In the OCaml build gaps G1 to G4 are already closed by the minimal version; see section 10.

Product version. Adds trace 4 with a live index refresh, and checks 10 and 13 under load. It also adds four-star keys, saved constellations and drawing for a friend, each with its own traces.
